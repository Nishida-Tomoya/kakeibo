## 2. 参考システム（base_system）の調査

ユーザーがフォルダ名を `receipt-analyzer-pro-&-household-ledger` から `base_system` に変更したうえで、中身を調べた。

### 機能
| 画面 | 機能 |
|---|---|
| 入力 | 支出・収入の手入力。レシート画像を Gemini に読ませて、店名・日付・合計・品目ごとのカテゴリを自動入力 |
| レシート | 保存したレシートの一覧・検索・削除 |
| メール取込 | カード利用通知メールの本文から、AI が金額を抜き出す |
| 集計 | 月ごとの収支、カテゴリ別の円グラフ、過去6か月の棒グラフ |

### AI の呼び出し方
`base_system` は **Google Cloud の Vertex AI（有料の従量課金サービス）経由で Gemini 2.5 Flash を使う**仕組みだった。

```
ブラウザ（frontend/services/geminiService.ts）
  → 通信を横取りして自分のサーバーへ転送（frontend/vertex-ai-proxy-interceptor.js）
  → サーバーが PC の Google 認証情報を付けて Vertex AI に中継（backend/server.js）
  → Gemini が結果を JSON で返す
```

認証情報をブラウザに置かず、サーバー側で付け足す設計。この考え方は新しい `app/` でも同じにしている（AI のキーはサーバーだけが持つ）。

### 問題点（作り直した理由）
- データはブラウザの中（localStorage）だけに保存される。ブラウザのデータを消すと消え、スマホと PC で共有できない。
- 登録した明細の一覧・修正・削除の画面がない。
- AI を使うには Google Cloud の設定と支払い登録が必要。

## 4. 作ったもの（app）

### 構成
| 部分 | 使った技術 | 場所 |
|---|---|---|
| 画面（フロントエンド） | React + TypeScript、Vite、Tailwind CSS、Recharts（グラフ） | `app/web/` |
| サーバー（バックエンド） | Node.js + Express + TypeScript | `app/server/` |
| 共通コード | カテゴリ定義、レシート内訳の計算 | `app/shared/categories.ts` |
| データ | SQLite のデータベースとレシート画像 | `app/data/`（自動で作られる。GitHub には上げない） |

### 画面と機能
| タブ | 機能 |
|---|---|
| 入力 | 支出・収入の手入力。支出はレシートを撮影すると AI が読み取り、内容を確認・修正してからカテゴリごとの内訳として登録 |
| 明細 | 月ごとの明細一覧。タップで修正・削除 |
| レシート | 保存したレシートの一覧（店名検索・月で絞り込み）。品目・画像の確認。削除するとそのレシートから登録した明細も一緒に消える |
| 集計 | 月の収入・支出・収支、カテゴリ別円グラフ、過去6か月の推移 |
| 設定 | 家族のアカウント追加、LINE レポートの下書き確認と手動送信、ログアウト |

### データベースのテーブル（`app/server/src/db.ts`）
| テーブル | 内容 |
|---|---|
| `users` | ログインするユーザー（家族それぞれ）。パスワードは scrypt という方式でハッシュ化して保存 |
| `sessions` | ログイン状態（30日間有効） |
| `transactions` | 家計簿の明細（収入・支出）。レシートから登録したものは `receipt_id` でレシートとつながる |
| `receipts` | 保存したレシート（店名・日付・合計・品目）。画像は `app/data/receipts/` にファイルで保存 |
| `line_reports` | LINE に送った月次レポートの記録（同じ月を二重に送らないため） |

### 主な仕組み
- **ログイン**：最初に開いたときに1人目のアカウントを作り、2人目以降は「設定」画面から追加する。全員が同じ家計簿を共有する。ログインの総当たりを防ぐため、ログインは15分に20回までに制限。
- **レシートの内訳計算**：レシートの品目は税抜のことが多いので、カテゴリごとに合計してから、税込の支払総額に合わせて比例配分する（`base_system` の計算を `app/shared/categories.ts` に移した）。
- **LINE 月次レポート**（`app/server/src/services/line.ts`）：毎月1日9時（日本時間）に前月の収支とカテゴリ別内訳を送る。その時刻にサーバーが止まっていた場合は、その月の7日までに起動すれば未送信分を送る。
  - 以前よく使われた「LINE Notify」は2025年3月に終了したため、LINE 公式アカウントの Messaging API を使う。無料プランは月200通まで。

## 6. レシート読み取りの AI を Gemini の無料枠に変更した経緯

1. **Claude API は有料**：Claude Code（Pro/Max プラン）を使っていても、自作アプリから Claude を呼ぶ分は別料金（Claude Console で従量課金）。サブスクリプションのログイン情報をアプリに流用するのは利用規約で認められていない。
2. **無料の方法を検討**：Gemini API の無料枠、文字認識（OCR）を自前で動かす、自分の PC で AI を動かす、手入力だけで使う、の4案から **Gemini API の無料枠**を選んだ。
3. **Google AI Pro（学生向け無料プラン）の特典を確認**：Google AI Pro には毎月10ドル分の Google Cloud クレジット（Gemini API の支払いに使える）が付くが、ユーザーの学生プランでは有効にできなかった。
4. **Gemini API 無料枠の条件**（2026年10月時点で調べた内容）
   - 無料で使えるのは Flash 系のモデル（`gemini-3.8-flash`、`gemini-3.5-flash-lite` など）。
   - 回数の上限は公式ページに数字がなく、Google AI Studio の画面で確認する。上限はプロジェクトごとにかかり、Google が随時変更している。
   - **無料枠では、送った内容（レシート画像）が Google の製品改善に使われる**。有料枠では使われない。
5. **API キーの発行**：Google AI Studio で、家計簿専用のプロジェクトを新しく作ってキーを発行した。既存のプロジェクトは支払い設定がつながっている可能性があり、有料扱いになるのを避けるため。支払い方法は登録していない。
6. **混雑への対策**：最初のテストで `gemini-3.8-flash` が「503：アクセス集中」を返したため、混雑中（503）や回数上限（429）のときは `gemini-3.5-flash-lite` で自動的にやり直すようにした。

### 関係するファイル（`app/server/src/services/`）
| ファイル | 役割 |
|---|---|
| `receiptPrompt.ts` | AI への指示文と、返してほしい結果の形（Gemini と Claude で共通） |
| `gemini.ts` | Gemini API を呼ぶ処理（混雑時のやり直しを含む） |

| `receipt.ts` | `.env` の `AI_PROVIDER` を見て、どちらを使うか切り替える |
